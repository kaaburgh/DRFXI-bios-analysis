# DRFXI 1.15: hidden UMC, direct HII form access and passive runtime diagnosis

2026-11-26. Scope: exact stock DRFXI 1.15; no live board writes, gate-opening calls, CMOS changes, flash, or private dump publication. User reported that replacing FormBrowser/DisplayEngine using zedk still showed only CPU/NBIO/FCH/SMU in CBS. AmiSetupFormSetVar absent; passive Shell readback and CRC-validated dmpstore export corroborate AmdSetupRPL size 0x6D5, Combo CBS 0x43, MCR FF (Auto), AMD_PBS_SETUP+0x91 = 1. These are owner observations, not a hardware run of this new tool. The supplied 16 MiB bios_afu.bin is a previous M75n image, not a DRFXI donor; do not use it for this task.

## Normal settings path and critical protection caveat

MCR QFlags=10 means reset required, not callback. No dedicated Q9B branch established in CBS callback. HII ConfigRouting dispatches by GUID/NAME/PATH to ConfigAccess. CbsSetupDxeRPL ExtractConfig RVA 0x894 reads full variable, initializes fallback at 0x95E, recalculates platform selector at 0x967, validates header 0x339C, BlockToConfig at 0xAD1. Not a guaranteed simple variable read.

RouteConfig RVA 0xB58 validates inputs and header (0x339C), ConfigToBlock at 0xBC6, full 0x6D5 SetVariable at 0xBFA (attributes 7), LocateProtocol APCB at 0xC24, sync 0x45C4 at 0xC38. At 0xC3D returns saved SetVariable status (RBX at 0xBFD), not APCB result; APCB protocol locate failure bypasses sync. Transfer reconstructs priority-3 settings, token FEDB01F8 from MCR +263 at 0x4EED..4EF9 when non-FF, Auto skips explicit token. APCB writeback at 0x5107; transfer returns zero at 0x5110, not independent writeback result. Startup sync uses mutable CBS fingerprint +8 (0x3C3C/0x5134; MCR included 0x5BDF). A successful RouteConfig is not an atomic or proven complete update of policy; full sync touches more than one setting. Factory APCB default Enabled; user's Auto/Enabled observation consistent. Prior checkpoint has complete lifecycle and retrain flag details. No live RouteConfig test, no no-op write test, no manual gate mutation. No safe write method proven while runtime lock remains active.

Critical correction to the older "read-only runtime probe" terminology: AmdVariableProtection is byte-identical on 1.15 and 1.17. PBS+91=1 is configured feature, not runtime state. Actual authenticated volatile gate AmdVariableProtection, GUID 408F573D-65EE-49ED-8BC5-5A32BBEAE745, attributes 0x26, byte1 activates VariablePolicy/VarCheck. Wrapper at 0x12F4 can remove the gate before forwarding HII routing ExtractConfig. DXE initialization/ReadyToBoot recreates it; late Shell may be after ReadyToBoot. Normal browser SendForm can traverse this path even without Save. **Do not run previous gate-opening probe or browser in the next passive experiment**. Do not intentionally call ExtractConfig (including NULL requests), RouteConfig, direct SetVariable, CMOS, or alter protection. Prior user's zedk browser session may have opened gate; not measured. Need fresh boot baseline. Normal UI-mediated config window may preserve PBS enabled but not continuous runtime locking; explicit owner consent and validated recovery would be needed before any such experiment. A later, controlled change needs complete before/after CBS and APCB verification and check of lock restoration, not just EFI_SUCCESS.
