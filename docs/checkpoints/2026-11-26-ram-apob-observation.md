# DRFXI RAM APOB observation and SPI comparison

Date: 2026-11-26. Read-only follow-up to the MCR/retrain lifecycle checkpoint. No original owner AFU or RAM APOB has been transferred; no hardware tests or firmware changes in this pass.

## Firmware evidence

Inputs: factory DRFXI 1.15 SHA-256 `3afaba6d916b3897d1d98bd5913008b38e89b6c51b2c6963c7109793541d8d88`, 1.17 `99f3bab5ea491202bf365c23e6416f9d1e8a649ad00f90c1f3e21f1a61e35c51`. Both known BL2 directories advertise type 0x61 RAM address 0x0A200000 and type 0x63 NV region offset 0x125000, capacity 0x28000. Owner's preceding equality-only report established a 72576-byte saved APOB identical across AC loss.

* AmdSocFl1RplPei TE, 33736 bytes, SHA-256 `fadf1f414fedb426bc4f00d0316bda91086fea5846c9193dbd2f8b39687c6ccb`, identical in 1.15 and 1.17. TE mapped disassembly: constructor at 0x9B74686; BIOS directory lookup with CL=0x61 at 0x9B746F3; APOB signature check at 0x9B7471F and table size from +8. Publishes supported/size/address fields in GUID HOB 30b174f3-7712-4cca-bd13-d0b8a8801997 (creation at 0x9B74783, GUID and data at +8/+0x18). Prefix consistent with public openSIL APOBLIB_INFO. Allocation helper called at 0x9B74810 after page-size rounding; type-2 memory allocation HOB helper 0x9B72434 stores physical address at +0x18, size at +0x20 and memory type 0xA at +0x28 (0x9B72473). This is EfiACPIMemoryNVS; expected reservation for the owner's table is 0x12000 bytes at 0x0A200000, inclusive end 0x0A211FFF. Actual OS memory map is not observed.
* ApobRplPei TE, 6336 bytes, SHA-256 `6e1b28da7d3b730a3e2a521c66239fccf9ac274efd686c37420c670be6472fd1`, identical across releases. HOB prefix lookup and signature verification (0x9B71551).
* ApobRplDxe PE, 13152 bytes, SHA-256 1.15 `47e631cda76df799fc7db0ca01b7d8c7937d9bd01b8e3527e72d04fbdd2bd57b`, 1.17 `72b66f99f33c79a95314b09fbe337780b2008f3657509ac3d8defd7cecd440ce`. Only three changed bytes, corresponding to PCD immediate renumbering 0x3EA->0x3ED (RVA 0xECD and 0x10BC) and 0x3EB->0x3EE (0x11DD). Accessor at 0x2348 obtains GUID HOB payload; routine around 0x24DB accesses Supported, ApobSize and ApobAddr, checks signature at 0x2523, version at 0x253E, walks entries.
* MemRestoreDxe ReadyToBoot callback at 0x730 clears failure bit 0 and sets signoff bit 2; V2 includes recovery check before signoff. This is not a positive MCR-execution indicator. A scoped search for MCR diagnostics in the extracted PE32/TE modules did not establish a separate OS-visible variable that records whether ABL actually took the restore branch. This is not an exhaustive proof of absence.
* Prior checkpoint establishes PSP compares RAM and SPI and writes when permitted and different. A RAM/SPI difference is not alone proof of new training: DXE updates, timing of acquisition, or non-persistence can affect the copies. No complete inventory of in-place APOB writes has been established. An exact match likewise does not exclude identical new training outputs.

## Acquisition and comparison

Existing ZenStates-Core acquires the complete table in `Apob.RawTable`; Windows ZenTimings source has Tools > Debug > Dump APOB table. This exports raw data to a local file. Keep both raw files private. Start a new normal application instance for a fresh cached snapshot; menu availability in the owner's installed build is not verified.

A standalone local Python comparator was delivered to the owner (compare_bd790i_ram_spi.py). It reads only two existing files, validates known DRFXI directories and bounded tables, checks DDR5 SPD identities locally, and writes an equality/count JSON report only. Existing outputs are refused. It does not disclose raw bytes, hashes, identity or date values, filenames or unknown register contents.

ZenTimings PR #28: https://github.com/kaaburgh/ZenTimings/pull/28 (tested head f11af3c2ae160258b918d5ababb2b8fb0d66f46f).
* Shared pure comparator; Windows APOB Info button compares cached live RawTable to a user-selected local AFU, no new hardware reads; disabled for mock/debug-report windows. Saves only JSON using CreateNew.
* Linux explicit --apob-compare-image AFU [--apob-compare-file APOB] [--json]. Live path requires recognized DRFXI, supported CPU, exclusively reserved/NVS range in /proc/iomem, reads only fixed known address through /dev/mem and requires two identical complete reads. Denial is final; no kernel or driver policy changes. Offline path opens only local files.
* Checks both known BL2 directories and checksums, bounded v0x18 tables, 26-entry persisted layout, unique entries, CRC-valid DDR5 SPD and matching nonblank identities for both DIMMs. Reports whole table/header/layout equality and known-record equality, counts changed bytes only for allowlisted records; identity-bearing records and training date use equality only. HMAC is not verified.
* Linux CI passed https://github.com/kaaburgh/ZenTimings/actions/runs/45875128716; Windows CI passed https://github.com/kaaburgh/ZenTimings/actions/runs/45875128746. First Linux run had missing LINQ import in smoke test, corrected. Actual WPF use on hardware untested.

Python tests included mutations of PMU/header/date, SPD CRC/identity mismatch, duplicate/truncated records, blank factory images and refusal to overwrite; no source changes. Actual CLI rejected factory 1.15/1.17 images without saved APOB and unrelated M75n layout. Existing --apob-image output unchanged relative to PR27 on donor and M75n; factory 1.15 remains unavailable. Live path on analysis container not available; no physical access attempted there.
