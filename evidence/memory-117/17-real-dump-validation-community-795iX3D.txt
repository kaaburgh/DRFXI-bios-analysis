## observations
- live NVRAM store is the *backup* NV area 0x1BC0000 (AMI alternates stores); 0x1BE0000 holds only StdDefaults -> the report scans both areas
- AmdSetupRPL header signature 0xFC4053AA and generation [0x08] = 0x4B9D5809 = override-APCB token on a board configured and saved through Setup:
  confirms that Setup saves do not change the generation and that no automatic resync is pending (corrected reading, checkpoint afu-coverage-and-dram-consumers)
- override APCB @0x522000 grew to 0x348 bytes and UniqueAPCBInstance 0x2732 -> 0x2733 (backup copy unchanged): a runtime APCB write bumps the ID
- the extra override type GNBG 0x1705/0x1002 sits in instance 0 with priority mask 0x10, the slot inferred for purpose-2 writes
- donor ran DRAM at Auto (no CBS timing tokens; AOD VDDIO Ctrl Auto, DIMM VDD/VDDQ 1100 mV, APU VDDIO 1100 mV)
