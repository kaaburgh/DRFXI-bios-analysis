## observations
- AMD Overclocking (AodSmm, purpose 2) writes land in override instance 0 with priority mask 0x02, not 0x10 as inferred earlier
  from the community dump's GNBG entry; CBS (purpose 3) uses instance 1 / 0x04. With fiano's level order AOD would outrank CBS.
- Memory Target Speed (0xD06DBAFB) is written only when AodSetupRpl[0x3C] == 1 AND [0x3A] != 1 (AodSmm 557D: cmp [rbx+0x3a],r13b; je skip);
  [0x3A] == 1 selects another path that writes 0xE753A04C = TRUE and 0x244E47D0 = [0x3B] instead (meaning of 0x3A/0x3B: INFERENCE,
  likely a memory-profile selector; the IFR questions are unnamed).
- the owner's memory configuration lives entirely in AMD Overclocking; the APCB holds exactly what those settings produce,
  no CBS resync is pending, APOB NV is populated (saved training), CBS Memory Context Restore is Auto (platform default TRUE).
- FCLK is stored as the CBS option code (AOD 2000 MHz -> 0x30); DIMM VDD/VDDQ 1200 mV become tokens 0x66CAD59B/0x814A6C32 plus two
  TRUE flags (0x6CD36DBE, 0x72958E2C); 'Enable Platform PMIC Control' = Disable becomes 0x288F8A28 = 0. APU VDDIO has no token.
- running DIMM voltages (owner's ZenTimings debug report, 2026-11-23): PMIC5100 in Secure mode, VDD/VDDQ set-points 1100 mV,
  SWA/SWB ADC 1095 mV -> the saved 1200 mV request is not applied (checkpoint 2026-11-23).
